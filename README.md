# RUBY自动补方案：渐进情绪测试版

这是独立的个人测试助手，不是RUBY官方版本；没有修改、复制或打包作者RUBY源码。当前版本0.1.3；维护者已完成本机安装、面板加载和已有任务拒绝路径检查。本次升级未调用模型。已有角色卡规则不会随扩展更新自动同步，真实模型效果与文件安装分别验收。

## 解决什么

为没有作者分析任务的现成卡补一份方案：优先找原卡的人设、渐进情绪、关系和知情边界规则，不另造人物。新的两条提示词按“小猫提示词.txt”的自然称呼、单行形式写。

- 常驻正文护栏：普通冷淡、尴尬、分歧、一次拒绝，不直接等于崩溃、悔恨、人格瓦解或好感归零。升级要有实际触发和已确认积累。
- 周期接续记录：每4条AI回复分析一次，分开记录当下反应、持续压力、关系变化、角色实际知情范围。严重事件和原卡明确的敏感点仍可引起强烈反应，不强迫所有人冷静。

不是固定情绪分数，不是新的MVU系统；不改MVU、柏宝书、预设、正文长度、原卡文字或原世界书条目。方案读到哪些内容不等于主角/NPC知道那些内容。原卡有任务，包括关闭的作者任务，本版直接跳过。

## 安装与使用

在酒馆“扩展 → 安装扩展”中填写本仓库地址：https://github.com/guhaojiang38-netizen/ruby-auto-emotion-helper 。安装后刷新页面。需要已安装并启用的RUBY Analyzer 1.8.0；本机运行检查环境为SillyTavern 1.19.0，清单最低版本1.18.0不代表其他版本已实测。先复制卡和主世界书，并给测试卡绑定独立的主世界书。未绑定世界书、检测到共用主书、群聊、素材过大或方案冲突时停止，不自动替换。

1. 扩展面板找到“RUBY 自动补方案 · 渐进情绪”。通常自动识别RUBY目录，找不到再填写实际目录名。
2. 小猫预设正文确实使用`<game>...</game>`时勾选相应项；没有这个格式的卡不勾。
3. 点击“自动选参考并生成草稿”。弹窗说明发送范围和计费；确认后，通过RUBY现有模型连接选择参考条目，校验每项的逐字证据。此步只保存本地草稿，不写卡。
   模型格式不合格时不会写入。也可选择“本地匹配生成草稿（不调用模型）”：按标题与内容线索挑选最多六条真实人设/情绪依据，不读取脚本或状态栏作为依据；这是规则匹配，不是模型理解，须检查是否包含该卡重要的阶段与场合规则。没有足够依据会停止。
4. 查看草稿，然后点击“保存关闭状态的方案”。先备份，再向测试卡的`data.extensions.RubyAnalyzer`写新方案、向主书新增3个关闭条目，写后重新读取核验。
5. 点击“启用这一份方案”才启用常驻护栏和一个周期任务。旧聊天不会重写。周期任务继续使用RUBY现有API，可能计费。
6. 换卡不会自动应用；有配置的卡照作者方案玩，无配置的卡各自生成一次。刷新后可点“读取这张卡的已有草稿”。
7. 升级助手后，可先读取已保存草稿，再点“同步助手规则（不调用模型）”。只更新助手自己的正文护栏和分析指令，保留参考、启用状态、周期和旧聊天；仅接受已核对的0.1.1、0.1.2和当前规则，人工改过的草稿、条目或任务键会拒绝覆盖。离线已更新世界书时，此按钮也能让旧浏览器草稿跟上，避免启停检查将版本差异误当成人工改动。更新扩展本身不会自动同步任何卡。

所谓自动，是自动挑选依据、拼装配置与周期分析；不是后台扫描并批量改所有卡。发送模型素材、写卡、启用各有一次明确按钮，避免误改和意外账单。

## 保存、回退与隐私

本地草稿和每次写入前的备份保存在当前酒馆网址的浏览器IndexedDB数据库`ruby-auto-emotion-helper`中，不含API设置。导出文件可能包含私人世界书，请不要公开。切换浏览器、端口或清除站点数据可能导致找不到草稿，建议另存导出备份。

写入不是服务器级原子事务：本助手先比较预览基线，写完再读取核验。遇到失败，只在内容仍与本次写入完全一致时尝试回退；发现其他人/插件修改就停止，保留备份，不覆盖并发修改。检查和写入之间仍有很短的并发窗口，请不要同时编辑卡片或世界书。

停用按钮关闭本助手的任务、护栏和当前聊天书中的同名记录，保留内容以便检查；其他聊天中的历史输出须分别停用。禁用/卸载这个独立扩展不会自动改已保存的卡内方案，请先点停用，再在RUBY面板确认任务关闭。没有做自动一键删除原书/还原整卡。

取消按钮阻止后续保存并丢弃迟到结果，不能保证终止已经发出的模型请求或撤销计费。助手每次生成只发一次逻辑调用；RUBY原有网络重试可能产生更多实际请求。

## 必须知道的边界

- 常驻规则只有真正进入正文提示词才有影响：世界书预算、禁用设置或其他指令冲突仍可能使它不生效，需要看真实发送内容。
- 周期记录是辅助判断，不保证模型遵守，也不能保证原卡隐藏/条件触发的情绪规则已经完整可见。复制进参考的宏/EJS会转成普通文字，不执行、不伪称得到当前变量值。
- 每4条回复分析会有延迟，本版本没有改RUBY的分析输出校验器。分析JSON格式和300～500字只是提示要求；RUBY仍可能保存格式或内容错误的非空返回。
- 小猫适配给RUBY添加`game`正文标签，并在启用时检查最近一条正文。仅当聊天只有一条、且它与酒馆展开宏后的作者开场白完全一致时，允许原开场白没有标签；后续无标签生成消息不会通过启用检查。**RUBY原始读取器在后续消息缺少正文标签时仍会退回整条消息**，本版没有改作者读取器，不能保证永远不读到菜单/摘要。独立正文提取单元测试不是RUBY实时过滤已生效的证据。
- 不自动开启柏宝书接口；保留已有`summaryProvider`设置。没有实际提供的记忆/MVU数据时，分析指令要求写“未提供”，不是读过所有插件的保证。
- 可检测通过角色列表绑定的共用主世界书，无法证明没有其他脚本或外部使用者共享它。因此仍须使用独立测试副本。
- 本版未做整卡安全审查，也不执行素材中的脚本或指令。大于65000字符的候选素材或大于20000字符的选中参考直接拒绝，不偷偷截断。

0.1.1修复：独立面板使用局部宽度样式，避免酒馆把中文按钮压成竖排；无草稿不能保存/启用；酒馆预组装提示词（dryRun）不再被误判成正在生成；常驻情绪规则增加阶段和场合约束，保留原卡允许的真实难过和独处反应。

0.1.2小修：作者侧阶段、路线和触发标签不进入正文、台词、选项及剧情摘要，机器变量和原卡要求显示的状态栏保留；连续得到安全回应后允许暂时缓和，不强制和好或快乐；正文和选项对照已知信息与物品交接、位置、数量，神人操作不凭空变出道具；分析记录区分计划、检查与完成。仍是模型指令，不是已实现的硬过滤，也不能补出缺失的MVU运行数据。既有选项数量、字数和正文风格不在本助手中改写。

0.1.3合并专用卡实测经验：分析新增“动作与约定来源”，不把角色回复里代写的玩家动作当成玩家确认；NPC条件和提议、旧分析中的无依据约定标待核实，并要求人物与顶层待办一致。通用助手没有专用MVU读取宏，年龄兼容只适用于实际提供给分析的字段：1至150整数及纯数字字符串可识别，非法值保持未知；没有新增变量采集或硬转换器。RUBY原读取器可以包含带角色标记的玩家原话，只有实际独立提供的原话才能用于确认。发现RUBY目录使用主文档URL基准并保留同源检查；书更新而配置不变时零配置写入，避免切卡时冗余回退阻断恢复；同步拒绝未知版本、手改草稿和重复/改键条目，忙时停止。正文护栏保持0.1.2，没有合并专用卡0.1.5的位置变更和0.1.6新增生成规则。离线与客户端证据见本轮回执，通用版新规则的真实模型分析效果仍待验证。

情绪验收至少用：普通拒绝、轻微尴尬、持续压力后的冲突、原卡明确创伤触发、严重损失、换场继续。比较“触发—中间反应—最终反应”是否连贯，不能用只检查关键词来证明修好情绪。
